# 名词大白话

> 页面上冒出来的行话，这里都用一句话说清楚。不按字母排，按你可能碰到的顺序排。

| 看到这个词 | 其实就是 | 通常在哪出现 |
| --- | --- | --- |
| 网关 / 接入地址 | 公司统一的 AI 入口地址。你的工具连它，不直接连厂商 | 快速上手、全部密钥 |
| 密钥 / API Key | 你调用公司 AI 的「门卡」。不要给别人，不要贴群里 | 我的密钥、全部密钥 |
| 打码串 / 脱敏串 | 密钥被遮住一部分的样子，只用来核对是哪一把，**不能用来调用** | 我的额度、我的密钥 |
| 虚拟模型 | 公司给员工统一起的模型名，例如 company-chat。工具里就填它 | 几乎每一页 |
| 真实模型 / 厂商模型 / 实例 | 虚拟模型背后真正干活的那个模型，可能来自不同厂商 | 接入管理、虚拟模型 |
| 主 / 备 | 平时用主模型；主模型出问题，自动切到备模型 | 虚拟模型 |
| 供应商 / 厂商 | 提供 AI 模型的那家公司 | 接入管理、模型配置 |
| 适配器 | 把不同厂商的接口「翻译」成统一格式的设置。一般系统会自动选好 | 模型配置、接入管理 |
| Token | AI 计费用的字数单位，大致比中文字数多一些。输入和输出分开算钱 | 账单、团队用量 |
| 单价 | 每千 Token 多少钱。没配单价，账单就显示 ¥0 | 接入管理、我的账单 |
| 额度 / 配额 | 一段时间里最多能用多少。可以按月，也可以按分钟、小时、天 | 我的额度、全部密钥 |
| 每月 1 号重置 | 月度额度到月初重新计算 | 我的额度 |
| 限流 | 短时间内调用太多就先挡一下，提示 429 | 全部密钥、虚拟模型 |
| 熔断 | 某个模型连续出错，系统先把它暂时停用，避免一直失败 | 全局配置、接入管理 |
| 失败阈值 | 连续错几次才触发上面的「暂时停用」 | 全局配置 |
| Trace ID / 调用编号 | 每一次调用的唯一编号。报障时报这个号，管理员能直接定位 | 调用观测 |
| 链路追踪 | 把一次请求从头到尾经过哪些步骤摊开看 | 调用观测 |
| 部门 | 账号上填的部门，用来在「团队用量」里按部门汇总 | 账号管理、团队用量 |
| 角色 | 用户＝只管自己；运维＝还能管团队；管理员＝全部，含系统设置 | 账号管理 |
| 共享存储 / 状态 | 多台网关一起跑时，大家共用的那份运行数据 | 状态监控 |
| fail-open | 额度服务出问题时「先放行还是先拦住」的开关 | 全局配置 |
| 配置版本 | 每次改配置都留一份存档，改坏了可以退回去 | 审计与版本 |
| 审计日志 | 谁在什么时候登录、改了密钥、改了配置的记录 | 审计与版本 |
| 金额额度 | 按「每月最多花多少钱」来限制用量，和 Token 上限并存；超过就拦 | 全部密钥、租户管理 |
| 高级计价 | 比普通单价更细的计价方式：阶梯价（一次调用越多越便宜）、时段价（按峰谷时段定价） | 接入管理、全局配置 |
| 隐私打码（PII 脱敏） | 把手机号、身份证号这类隐私在**写进日志前**替换成 138****5678 的样子；发给模型和用户的内容不变 | 全局配置 → 其他 |
| 敏感信息防泄漏 | 请求或响应里出现不该外传的内容时，直接拦截或替换，防止泄密 | 企业管理 → 安全能力 |
| API 密钥加密保管 | 厂商的 Key 加密存放，页面上看不到明文，防泄露 | 企业管理 → 安全能力 |
| 内容审核 | 给模型回复打分，分数过低（违规可能性大）就拦截 | 企业管理 → 安全能力 |
| 租户 | 一个独立的「公司空间」：账号、密钥、账单互相看不见 | 租户管理（企业版） |
| 合规证据 / 合规归档 | 把审计记录串成防篡改的链条并锁定存档，给合规检查用 | 审计与版本（企业版） |
| 部门登记表 | 把部门先登记进系统，每个部门有稳定编号，供统计和按部门设额；账号编辑的部门下拉只认登记过的部门 | 账号管理 → 新增部门（企业版在「组织」子页签） |

> 有些词后面跟着 401 / 403 / 404 这样的数字：401 是密钥不对，403 是没权限，404 是这个名字找不到。记住这三条就够用了。
